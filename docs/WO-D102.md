## Scope — one mechanism, four changes

1. **Derivation, exported and reusable** (new function, e.g. `engine/src/frontage.ts` or in `combat-config.ts`'s module space): `frontageMeters(unit, scenario) = (dismounted AND formation === 'SKIRMISH') ? unit.strengthAvailable × metersPerFiringMan : 0`. **`metersPerFiringMan` is a new `[CAL]` in the global combat table, value 4.57, with its one-sided sourced range documented in the provenance comment verbatim from D102(b)**: best 4.57 (Upton ¶610, SOURCED-verbatim) / low 0.914 (Carpenter, SOURCED-WEAK) / high NONE, deliberately — do not invent an upper bound. The function is exported because C's feature-capacity ruling is expected to derive occupancy from it — write it to be reused, not combat-private.
2. **Effective fire range** (`combat.ts`): `resolveFire` receives `effectiveRange = max(0, engagement.rangeMeters − (frontageMeters(attacker) + frontageMeters(target)) / 2)` in place of the raw descriptor range for hit-probability lookup. **The engagement descriptor's `rangeMeters` stays centroid** — the 700 m opening gate, the UI, disengage/charge state thresholds, and all existing consumers are untouched. Only the range fed to `rangeProbability` changes.
3. **Endpoint-overlap flank** (`combat.ts` `isFlanking`): a target with nonzero frontage is a line segment centered on its position, axis perpendicular to `facingRadians`, half-width `frontageMeters/2`; flanking = the existing angular test OR the attacker's along-axis projection falling beyond either endpoint. **Instrument endpoint-flank separately** (its own counter/flag distinct from angular flank) — it has no baseline and angular flanking already runs 56–77% of engaged ticks; conflating them would make both unscoreable. D96's closing trigger semantics are UNCHANGED — this makes flank computable for future rulings, it does not change what closes.
4. **Tests**: named tests for the derivation scoping (dismounted-SKIRMISH nonzero, mounted zero, warrior zero), the centroid-opening invariant, the effective-range subtraction, and the endpoint-flank geometry (beyond-endpoint attacker flags endpoint-flank; abeam within the segment does not).
