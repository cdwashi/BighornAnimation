## Scope — one function, three ruled changes, one round

All three changes are confined to `routeToSafety` in `engine/src/morale.ts`:

1. **Failure does not wipe a live path.** When the corridor search fails, a unit with an unconsumed path (`pathIndex < path.length`) KEEPS that path and continues on it. `blockedReason` is set only when no live path remains. The failure branch must not clear `path`/`pathIndex` when a live path exists.
2. **Origin-bubble exemption.** The interdiction blocker does not test points within `enemyInterdictionRadiusMeters` of the routing unit's own position at search time (structural reuse of the same config constant the corridor test already consumes — no new number). Interdiction semantics beyond the origin bubble are unchanged.
3. **Failure is not a latch; retry on the D92 cadence.** A failed search does not set `routSafetyPath`. It re-attempts no sooner than `pursuitRepathCadenceTicks` (10 ticks) after the previous failed attempt — a retry-timestamp needs a home; follow the existing `lastPathAttemptTick` pattern (`campDefense`, D92(a) lineage) rather than inventing new machinery. The SUCCESS latch is unchanged: a found safety path is held, exactly as today. Rally/reintegration semantics (`routRallyMorale`, `rout-reintegrated`) are untouched.

**Tests**: named tests for rout-keeps-live-path (a routed unit with an unconsumed path whose corridor search fails continues on that path), rout-origin-exemption (a corridor search succeeds when the only interdicted points lie within the origin bubble), rout-retry-cadence (a failed search re-attempts only after `pursuitRepathCadenceTicks`, and not every tick), and success-latch-preserved (a successful search still latches).
