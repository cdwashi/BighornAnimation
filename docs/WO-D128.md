## §0 — The claim

ONE claim, ruled at D126's repackaging: **"the BOM/CRLF gate works."** A gate works when
every vehicle carrying its predicate returns the predicate's verdict — on every input the
repository can present, including the inputs that exist because the gate's own scar does.

The pre-authorisation measurement (§1) found the claim false in THREE ways across the two
vehicles, one of them new at this drafting. All three repairs land under this one claim;
whether the third belongs here is flagged for adjudication in §6.

## §1 — The measured world (every figure from a committed instrument; nothing asserted)

**Instruments:** `.claude/gate-repair-enobufs-probe.mjs` (mechanism),
`.claude/gate-repair-msg-census.mjs` (history census),
`.claude/gate-repair-matrix-probe.mjs` (the offense matrix, a throwaway temp repo — zero
project-repository bytes touched), each with its `.out.txt` beside it. Measured at HEAD
`81f5909`, 2026-08-06, git 2.54.0.windows.1, node v24.15.0.

**Defect 1 — scale (the suite test).** `tests/repository-text-integrity.test.ts` reads
each blob through `execFileSync('git', ['show', ':path'])` with Node's DEFAULT `maxBuffer`
(1 MiB). Under the gate's own filter the index holds 434 tracked text files, aggregate
10,941,597 bytes; **433 of 434 read individually clean through that exact call shape; the
single failure is `.claude/repath-event-log.out.txt`, 2,708,511 bytes — ENOBUFS — and the
same blob reads clean under an explicit 64 MiB buffer.** The gate dies on its first
over-cap blob and never reaches a verdict on anything.

*Diagnosis correction, flagged for a dated annotation on D126 (adjudication's call, not
this WO's):* the D126 row and WO-D126 §4 state the overflow as "10.9 MB of tracked text
through one subprocess" with the AGGREGATE as the ceiling. The measured mechanism is
per-blob calls with a per-call cap: the ceiling is the LARGEST SINGLE BLOB, crossed today
by exactly one artifact, and aggregate growth does not re-arm it — single-artifact growth
does. **D126's ruled fix survives its corrected rationale unchanged:** a raised `maxBuffer`
still re-arms on the next larger single artifact (and event-log artifacts demonstrably
grow); per-blob streaming against a bounded buffer has no expiry. The ruling is not
relitigated; the rationale is corrected.

**Defect 2 — subjects (both vehicles; catches 37/38).** Neither vehicle reads commit
messages — the very thing the gate's founding scar was. The census scanned all 218
commits reachable from HEAD: **exactly two carry a BOM at message offset 0 — `94b4045…`
(catch 37, `8759dd0` governs) and `8759dd06…` (the original scar the D110 row promoted
"from prose to gate") — and zero carry a CR anywhere.** Both are permanent
(recorded-not-rewritten, the governing precedent); they are the allowlist, and the matrix
confirms the mechanism class: a BOM'd `-F` message file survives `git commit`'s default
cleanup byte-for-byte (cell M2), EOL CRs are stripped by default cleanup (M3) but survive
`--cleanup=verbatim` (M4), and interior CRs survive default cleanup (M5).

**Defect 3 — the hook's CR leg, NEW at this drafting (the matrix found it).** Matrix
cells B3 and B5: the committed pre-commit hook PASSES CR-bearing blobs that both the
suite predicate and the reference oracle FAIL. Isolated mechanism (disclosed measurement,
2026-08-06, Git Bash on this machine): Git-for-Windows' MSYS2 grep opens files in text
mode and strips EOL CRs before matching, so `grep "$(printf '\r')"` returns NO MATCH on
a CRLF file (`a\r\nb\n` → exit 1) while matching an interior CR (`a\rb\n` → exit 0).
**The hook is blind to precisely the CRLF class it was built for and sighted only on the
rare interior-CR class — inert on its platform since D110.** Its BOM leg is sound at all
sizes (B2, B6 caught; B4 large-clean passed; B7 false-positive control passed): the hook's
temp-file streaming survives scale; only its CR predicate is broken.

**The matrix (the measured counterfactual, per-cell in
`.claude/gate-repair-matrix-probe.out.txt`):** seven blob cells × {OLD gate mechanism,
reference oracle, real hook} + five message cells × {OLD = NO-COVERAGE, reference
oracle}. OLD's three ERROR(ENOBUFS) cells are defect 1; OLD's five NO-COVERAGE cells are
defect 2; HOOK's two false-PASS cells are defect 3; B7 (BOM not at offset 0) passes every
column — the false-positive control the repaired gate must also pass.

## §2 — The payload (Codex; fresh exec; fix-nothing outside this section)

**T1 — suite test, scale clause.** Rework the blob walk in
`tests/repository-text-integrity.test.ts` to stream per-blob against a bounded buffer:
memory bounded regardless of largest-blob size, no raised `maxBuffer` as the mechanism
(D126's ruled fix, rationale corrected in §1). Candidate route: one `git cat-file --batch`
child consuming the `ls-files` set with incremental chunk scanning (BOM = blob bytes 0–2;
CR = any 0x0D in any chunk). **Route is Codex's declared choice (D126's T3 convention):
the report DECLARES the route; if its red surface differs from §4's enumeration, the
difference is REPORTED, not reconciled.** The gate's filter, fail-loud-no-git behavior
(D110 Amendment 3), and the 120 s test budget are preserved. **Root override, required
for §3(b):** the test accepts a repository-root override (an env var read at test start,
e.g. `D110_GATE_REPO_ROOT`, defaulting to the live repo via `rev-parse` exactly as now).
This exists so the ACCEPTANCE runs the TEST ITSELF against the matrix repo — the vehicle,
not a replica of its logic. A replica-based acceptance is probe-verified where §3(d)
demands suite-verified; the OLD column in §1's matrix was legitimately a replica because
it was diagnosis with disclosed equivalence — the repair's acceptance may not be.

**T2 — suite test, subjects clause.** Same file (or a sibling in the same suite): walk
every commit reachable from HEAD; assert each message (bytes after the commit object's
first `\n\n`) carries no BOM at message offset 0 and no CR byte — EXCEPT the two-hash
allowlist `94b404528ac0c88eae796a534ee1515e47219ec2`,
`8759dd06311281951c8ea7089a5f05a7daf1e6fe`. **Allowlist-integrity assertion:** each
allowlisted hash still exhibits exactly its recorded offense (BOM, no CR) — a typo'd or
rotted allowlist goes red, and a third scar can never hide behind the first two.
**Partial-history branch, fail-loud (Amendment 3's philosophy):** on a shallow or
partial clone (`git rev-parse --is-shallow-repository`, or an allowlisted hash absent
from the walk) the test FAILS LOUDLY naming the condition — never a vacuous pass over
truncated history, never a silent skip. Fresh-clone verification is a stated property of
this test, not a discovery.

**T3 — commit-msg hook, NEW.** `scripts/hooks/commit-msg` (sh, same conventions as its
sibling): receives the message-file path, rejects BOM-at-offset-0 or any CR byte, naming
the offense. Byte-true predicates only — `od`-based, per §1's defect 3; no bare `grep`
on raw bytes. Self-test obligation as D110 Task 4b's: in a temp repo, a commit driven by
a BOM'd `-F` file is REJECTED, a clean one is ACCEPTED, and (per M5) an interior-CR file
is REJECTED. Activation rides the existing `core.hooksPath scripts/hooks` — no config
change.

**T4 — pre-commit hook, CR leg only.** Replace the `grep "$(printf '\r')"` line with a
byte-true check (the `od` route measured working in §1). The BOM leg and every other line
untouched; the repaired hook must go FAIL(CR) on matrix cells B3/B5 while B1/B4/B7 stay
PASS and B2/B6 stay FAIL(BOM).

**Untouched, declared:** everything else. No scenario byte (content hash byte-identical,
checked in the report — every stream-tagged figure under `68325eff` stays valid), no
engine source, no RNG site, no schema, no reseed.

## §3 — Acceptance: how a repair to the acceptance instrument is accepted

*The named open question, answered. The instrument cannot certify its own repair; while
under repair it is DEMOTED TO SUBJECT, and its office is held by instruments that share
nothing with it.*

**(a) The reference oracles, frozen here with commands and predicate mappings stated
(fifth practice: provenance at the point of citation).** Blob-CR:
`git grep -I --cached -P '\r'` — git-native, line-scoped; a CR byte always lies within
some line, so path-level presence is equivalent to the gate's CR-anywhere predicate; the
`-I` binary skip plus the gate's extension filter reproduces WO-D126 §4's exclusion of
its four incidental binary matches. Blob-BOM: `git show :path | od -An -tx1 -N3` under
sh, first three bytes `efbbbf` — chosen over git-grep because grep would also flag BOM
bytes mid-file, which the gate's offset-0 predicate deliberately permits (control cell
B7). Messages: `git log -1 --format=%B <sha> | od -An -v -tx1` under sh — BOM = first
three bytes, CR = any `0d`. These share no implementation with the Node test: git
plumbing and `od` on one side, `execFileSync` buffers on the other. **B7 is the oracles'
own self-check (ruled at freeze): an oracle that fails B7 — BOM bytes not at offset 0 —
is over-triggering, and its FAIL columns mean nothing. The oracles pass their control
before their verdicts are trusted.**

**(b) Reproduce-the-measured-world (D127's form).** The matrix was measured BEFORE this
authorisation. Acceptance is the repaired world reproducing the REF column CELL-FOR-CELL:
**the repaired suite test — the vehicle itself, run against the matrix repo via T1's root
override, never a replica of its logic** — on the matrix repo's cells; the repaired
pre-commit hook on B1–B7; the new commit-msg hook on the M-class message files. Any cell
where a repaired vehicle disagrees with REF is a defect or a finding — never a surprise.
**B5 is the acceptance's KEYSTONE (ruled at freeze): CR past the 1 MiB boundary is the
one cell where every defect meets — the old gate ERRORs, the oracle FAILs, the hook
PASSes. A repaired gate passing every cell but B5 has fixed the symptoms and not the
claim.**

**(c) Agreement on the real repository.** Repaired test and reference oracles agree on
the live index (both: zero offenses over the current tracked-text set, count re-derived
at run — the 434 will have drifted and that drift is expected, the oracle re-runs) and on
the live history (both: exactly the two allowlisted hashes, allowlist-integrity green).

**(d) Suite-vehicle green (a probe-verified world is not a suite-verified world).** The
repaired test runs INSIDE the full vitest suite and returns a verdict there. **The
ENOBUFS red is PAYLOAD-REMOVED AND THAT IS THE CLAIM: present at the §4 dry-run, ABSENT
at acceptance. Its persistence post-payload means the WO failed.**

**(e) The instrument's own failure mode preserved.** Fail-loud-no-git (Amendment 3)
re-verified: git unreachable → loud error, never a silent skip. Both hooks' self-tests
pass; `scripts/hooks/pre-commit`'s diff is exactly the T4 line.

**(f) Succession.** Only after (a)–(e) does the repaired gate resume its office as an
acceptance instrument. The reference oracles retire to the record; they are diagnosis
tools with disclosed provenance, not standing gates.

## §6 — Adjudicated at freeze (Fable, 2026-08-06; rulings transported in the message body)

1. **The D126 diagnosis annotation LANDS** (committed with this freeze). The corrected
   ceiling — `execFileSync`'s 1 MiB per-call cap against the largest single blob, not the
   aggregate — changes the prediction: aggregate-through-one-buffer implies the gate
   degrades as the repo grows; per-blob-cap means it degrades the moment ANY single
   artifact crosses a megabyte — and the second is already true. The ruled fix survives
   unchanged, which is why this is an annotation and not a relitigation.
2. **Defect 3's fix rides this WO.** One claim across all three defects — "a hook that
   runs at scale and misses CRs does not satisfy it." The shared-acceptance-claim line
   drawn twice at D126 holds.
3. **THE FORTY-FIFTH CATCH, the adjudicator's own.** He ruled the hook at D110,
   specified the predicate (BOM at offset 0, any CR) and its self-test in one pass — and
   the self-test he ordered staged a synthetic BOM'd file only: one leg exercised, the
   gate called proven, the CR leg never worked. Third structural gap in the D110 gate
   family, all three the adjudicator's (subjects uncovered; the ENOBUFS ceiling; the
   half-blind predicate). The pattern, named: **a self-test written by the predicate's
   author tests what the author thought of** — which is the argument for §3's independent
   reference oracles.
4. **The §3 acceptance structure stands** — demote-to-subject is the correct
   construction; the constraint that makes it work is the no-shared-implementation rule —
   amended with B5 as the acceptance keystone (§3b) and B7 as the oracles' self-check
   (§3a).
