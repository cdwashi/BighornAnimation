## §3 — Hypotheses, registered BEFORE any source opens

*Neither the vitest source nor its issue tracker has been read for this item; the RPC
timeout's configured duration is a fact to be READ, not assumed. Reads happen after this
document freezes, dated, with provenance (fifth practice).*

- **H1 — main-thread starvation:** the worker's `onTaskUpdate` RPC to the main process
  times out while the main thread is blocked (reporter/bookkeeping work during long
  synchronous engine tests). Discriminator: instrumented fire timestamps correlate with
  a specific test/phase window across runs.
- **H2 — teardown race:** the RPC is in flight when the run ends and the main side stops
  servicing calls; the timer expires during teardown. Discriminator: fire timestamps
  land after the final test's completion, in the teardown window.
- **H3 — upstream defect with a named fix:** the exact error string matches a known
  vitest 3.x issue fixed in a later release whose changelog names the mechanism.
  Discriminator: the upstream read; then a version bump must reproduce clean under
  Route M's confirming runs. (A bump whose changelog does NOT name the mechanism is
  Route S evidence at best, not Route M.)
- **H4 — environment-specific interaction** (Windows named pipes / process transport
  under this machine's Node 24): held as the residual hypothesis if H1–H3 discriminators
  all fail — it has no cheap discriminator and must not absorb blame by default.
